# Dependency pre-bundling cache never invalidates for Yarn with `nodeLinker: pnpm` (issue #23666)

### Describe the bug

Vite decides whether to re-optimize by hashing a package-manager file (`lockfileFormats` in `packages/vite/src/node/optimizer/index.ts`). For Yarn it only checks `node_modules/.yarn-state.yml` and `.pnp.cjs`.

Yarn 4 with `nodeLinker: pnpm` writes neither, so `getLockfileHash` hashes an empty string. `lockfileHash` in `node_modules/.vite/deps/_metadata.json` is always `e3b0c442` (sha256 of ""), and dependencies are never re-bundled after `yarn install`. Dev keeps serving stale deps until `--force` or manual cache removal.

Observed on Vite 8.3.0/8.3.3 and Yarn 4.1.1.

### Reproduction

https://github.com/aotradovec/vite-yarn-pnpm-linker-repro (Yarn 4.1.1, Vite 8.3.3, steps in the README)

### Steps to reproduce
1. `yarn install`. `node_modules/.yarn-state.yml` and `node_modules/.pnpm` do not exist.
2. `yarn dev`, open the page so `lodash-es` is pre-bundled, stop the server.
3. Bump `lodash-es` from `4.17.20` to `4.17.21`, run `yarn install`.
4. `yarn dev` again and open the page.

`node_modules/.vite/deps/_metadata.json` is identical before and after the bump:

| | before | after |
|---|---|---|
| `lockfileHash` | `e3b0c442` | `e3b0c442` |
| `browserHash` | `027c8571` | `027c8571` |
| installed `lodash-es` | `4.17.20` | `4.17.21` |

No "Re-optimizing dependencies because lockfile has changed" message is logged, and the pre-bundled `lodash-es` still contains `"4.17.20"`. `yarn dev --force` re-bundles it (`browserHash` changes to `98c43502`), but `lockfileHash` is still `e3b0c442`.

Observed on Vite 8.3.0 and 8.3.3.

### Proposed change
Add the source `yarn.lock` as a last-resort entry in `lockfileFormats`, after the existing Yarn entries so `.yarn-state.yml` and `.pnp.cjs` still win. This follows the existing `bun.lock` entry, which is also a source lockfile.

```ts
{ path: 'yarn.lock', checkPatchesDir: '.yarn/patches', manager: 'yarn' }
```
