# [dev] Vue SFC with `lang="tsx"` fails to compile: core `vite:oxc` parses TS as JSX-only when plugin-react is present (issue #23644)

## Actual

  Dev fails to compile the SFC script virtual module. The error response reports:

  ```
  Transform failed with 1 error:

  [PARSE_ERROR] Expected `from` but found `{`
     ╭─[ App.vue?vue&type=script&setup=true&lang.tsx:2:13 ]
     │
   2 │ import type { Props } from './types'
     │             ┬
     │             ╰── `from` expected
  ───╯
  ```

  - plugin: `vite:oxc`
  - id: `/path/to/App.vue?vue&type=script&setup=true&lang.tsx`
  - stack: `transformWithOxc → TransformPluginContext.transform → EnvironmentPluginContainer.transform → viteTransformMiddleware`

  Any TS-only syntax in the script block fails the same way (type annotations, generics, `as` casts). It appears the core oxc transform parses this
  virtual module with JSX enabled but TypeScript disabled.

  ## Expected

  The module compiles. Differential matrix (all verified on the repro above):

  | Stack | Result |
  |---|---|
  | vite 8.3.2 + plugin-vue + plugin-react 6.1.1 | ✗ fails in dev |
  | rolldown-vite 7.3.1 + plugin-vue + plugin-react-oxc 0.4.3 | ✗ fails in dev (same error) |
  | rolldown-vite 7.3.1 + plugin-vue only (no react plugin) | ✓ works |
  | rolldown-vite 7.3.1 + plugin-vue + plugin-react 4.7.0 (babel) | ✓ works |
  | `vite build` with the failing setup | ✓ succeeds — **dev only** |
  | `lang="ts"` SFCs, and real `.tsx` files | ✓ unaffected |

  So the trigger is specifically: (react plugin with oxc backend present) × (plugin-vue's `lang.tsx` script virtual module) × (dev transform).

  Possibly relevant: the virtual id ends with `lang.tsx`, which also matches the react plugin's include pattern (`.tsx$`), so an interplay over who owns TS/JSX handling for these modules may be involved — but the failing pass itself is the core `vite:oxc` transform.

  ## Workaround

  A small dev-only shim that pre-transforms these ids before the core plugin sees them (works on both the vite 8 and rolldown-vite 7 pipelines):

  ```js
  import { transformSync } from 'esbuild'

  function vueTsxDevShim() {
    return {
      name: 'vue-tsx-dev-shim',
      enforce: 'pre',
      apply: 'serve',
      transform(code, id) {
        if (!id.includes('.vue') || !/[?&]lang\.tsx($|&)/.test(id)) return
        const r = transformSync(code, { loader: 'tsx', jsx: 'automatic' })
        return { code: r.code, map: r.map ?? null }
      },
    }
  }
  ```

  ## Context

  Found in a VitePress site that mixes Vue SFCs with React islands: `lang="tsx"` SFC wrappers around React components rendered through a React-in-Vue bridge (6 such components, all broken in dev after moving to the oxc-backed react plugin).
