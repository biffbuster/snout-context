# fix: dep-scan misses imports whose local name starts with "type" (issue #23471)

### Describe the bug

`importsRE` in `packages/vite/src/node/optimizer/scan.ts` uses `(?!\s+type)` to skip TypeScript `import type` statements. Because there is no word boundary after `type`, any value import whose binding starts with the letters `type` is treated as a type-only import and skipped by `extractImportPaths`.

This is already noted as a false negative in `scan.spec.ts` (commented-out cases for `import typescript from 'typescript'`).

Affected examples:

```ts
import typescript from 'typescript'
import typeorm from 'typeorm'
import types from 'types'
```

These can be dropped from the TS/`<script setup>` crawl assist path, so esbuild may not discover those deps during optimize-deps scanning.

### Reproduction

Unit-level:

```js
const importsRE = /(?<!\/\/.*)(?<=^|;|\*\/)\s*import(?!\s+type)(?:[\w*{}\n\r\t, ]+from)?\s*("[^"]+"|'[^']+')\s*(?=$|;|\/\/|\/\*)/gm
importsRE.exec(`import typescript from 'typescript'`) // null (bug)
```

With `(?!\s+type\b)` the same import matches correctly while real `import type` forms still do not.
