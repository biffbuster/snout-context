# transformIndexHtml('/?query') adds the filesystem root to the watcher since 8.3.3 (issue #23679)

### Describe the bug

Since Vite 8.3.3, calling `server.transformIndexHtml(url, html)` with a root URL that has a query string (e.g. `/?foo=bar`) makes the dev server add the **filesystem root `/`** to the file watcher, as long as the HTML contains an inline `<style>`. This is the call shape from the [SSR guide](https://vite.dev/guide/ssr#setting-up-the-dev-server) (`transformIndexHtml(req.originalUrl, template)`), so any SSR setup that follows it hits this on a request like `/?utm_source=x`.

On Linux, chokidar then crawls the entire filesystem with one `fs.watch` per file. We hit it in a framework's integration tests: the dev server became unresponsive and the process ran out of heap (~4 GB) within a few minutes. On macOS the watch is cheap (FSEvents), so it's easy to miss locally.

It looks like a regression from #23653. `getHtmlFilename()` now strips the query, so for `/?foo=bar` the `filename` becomes the project root directory:

[link removed]

But `devHtmlHook` still runs its trailing-slash check on the unstripped `htmlPath` (`/?foo=bar`). `fs.existsSync(filename)` is true for the directory, so the URL gets treated as a real HTML file, and `proxyModulePath` becomes `/?foo=bar`:

[link removed]

Each inline `<style>` proxy module (`/?foo=bar?html-proxy&direct&index=0.css`) then has `mod.file === '/'`. `ensureWatchedFile()` doesn't skip it, because it isn't under `root`, has no `\0`, and exists, so it calls `watcher.add('/')`:

[link removed]

Before #23653 the filename included the query, `existsSync` was false, and the proxy module was virtual (`\0/?foo=bar`), so nothing was watched.

Possible fixes: compute `trailingSlash` from the query-stripped path, or only treat `filename` as an HTML file when it is a file (not a directory).

Expected: `transformIndexHtml('/?foo=bar', html)` behaves like 8.3.2 and doesn't watch `/`.

### Reproduction

Self-contained script (no repo needed). Save these two files in an empty directory:

`package.json`

```json
{
  "name": "vite-transformindexhtml-watch-root",
  "private": true,
  "type": "module",
  "scripts": {
    "repro": "node repro.js"
  },
  "dependencies": {
    "vite": "8.3.3"
  }
}
```

`repro.js`

```js
import { createServer } from 'vite'

// Same shape as the SSR guide: transformIndexHtml(req.originalUrl, template),
// where the request is `/?foo=bar` and the template has an inline <style>.
const server = await createServer({
  configFile: false,
  root: import.meta.dirname,
  logLevel: 'silent',
  server: { middlewareMode: true },
  appType: 'custom',
})

const watched = []
const add = server.watcher.add.bind(server.watcher)
server.watcher.add = (paths) => {
  watched.push(paths)
  // Don't actually watch `/`: on Linux chokidar would crawl the whole disk.
  return paths === '/' ? server.watcher : add(paths)
}

const template = `<!doctype html>
<html>
  <head><style>body { color: red; }</style></head>
  <body><div id="app"></div></body>
</html>`

await server.transformIndexHtml('/?foo=bar', template)
await server.close()

const { version } = await import('vite/package.json', { with: { type: 'json' } }).then((m) => m.default)
console.log(`vite ${version}: watcher.add calls:`, watched)
console.log(watched.includes('/') ? 'BUG: the filesystem root "/" was added to the watcher' : 'OK: "/" was not watched')
process.exitCode = watched.includes('/') ? 1 : 0
```

### Steps to reproduce

```sh
npm install
npm run repro
```

The script creates a middleware-mode dev server, wraps `server.watcher.add`, and calls `server.transformIndexHtml('/?foo=bar', html)` with an inline `<style>`. It stubs out the actual `watcher.add('/')` call so nothing crawls the disk.

| Vite | Result |
| --- | --- |
| 8.3.0 | `watcher.add` not called |
| 8.3.2 | `watcher.add` not called |
| 8.3.3 | `watcher.add('/')` |

Only a root URL with a query triggers it: `/` and `/about?foo=bar` don't.
