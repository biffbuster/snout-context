# isShallow() returns false for shallow collection proxies (shallowReactive(new Map())) (issue #15792)

### Vue version

3.5.43

### Link to minimal reproduction

```js
import { shallowReactive, shallowReadonly, reactive, readonly, isShallow, isReadonly } from 'vue'

// plain objects work
console.log(isShallow(shallowReactive({})))      // true
console.log(isShallow(shallowReadonly({})))      // true

// collections don't
console.log(isShallow(shallowReactive(new Map())))      // false (expected true)
console.log(isShallow(shallowReadonly(new Map())))      // false (expected true)
console.log(isShallow(shallowReactive(new Set())))      // false (expected true)
console.log(isShallow(shallowReadonly(new Set())))      // false (expected true)

// sanity: the deep counterparts correctly report false
console.log(isShallow(reactive(new Map())))      // false
console.log(isReadonly(readonly(new Map())))     // true, so collection traps do handle their own flags
```

### Steps to reproduce

Call `isShallow()` on a proxy returned by `shallowReactive()` / `shallowReadonly()` where the underlying value is a `Map` or a `Set`.

### What is expected?

`isShallow()` should return `true`, matching the documented contract ("Checks if a value is a shallow reactive or shallow readonly object") and matching the behavior of the plain-object counterparts. `reactive()` / `readonly()` on collections report their flags correctly (e.g. `isReadonly(readonly(new Map()))` is `true`), so `isShallow()` should behave consistently.

### What is actually happening?

`isShallow()` returns `false`, because the collection `get` trap in `packages/reactivity/src/collectionHandlers.ts` (`createInstrumentationGetter`) handles the `__v_isReactive`, `__v_isReadonly` and `__v_raw` flags but not `__v_isShallow`, so the lookup falls through to `Reflect.get(rawTarget, '__v_isShallow')`, which is always `undefined`.

This is not just the predicate itself — `isShallow()` gates several internal code paths, and each of them misbehaves for shallow collections:

- `ref.value = shallowReactive(new Map())` (RefImpl setter) stores `toRaw(value)` and wraps it with `toReactive()`, so the user's shallow proxy is silently replaced by a deep reactive proxy.
- Assigning a shallow collection into a reactive object property (`state.m = shallowReactive(new Map())`) or into another reactive collection (`outerMap.set('m', shallowMap)`) likewise loses the shallow wrapper.
- `watch()` treats a shallow reactive collection as deep (`reactiveGetter` traverses more than one level).
- The devtools custom formatter labels `shallowReactive(new Map())` as `Reactive` instead of `ShallowReactive`.

Note that the existing test `The results of the shallow and readonly assignments are the same (Map)` only covers shallow *plain objects* stored inside a reactive Map, which works today — the collection-proxy case is uncovered.
