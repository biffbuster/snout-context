# `cloneLoc` uses the shared tokenizer: `v-if` loc and template source maps depend on the previously parsed SFC (issue #16091)

### Vue version

3.5.44 (the same code is on `main` and `minor`)

### Link to minimal reproduction

https://gist.github.com/nolequen/b66153cde6899e515b183efb9911750e

### Steps to reproduce

```sh
npm i @vue/compiler-sfc@3.5.44 source-map-js
node repro.js
```

```js
const { parse, compileTemplate } = require('@vue/compiler-sfc')
const { SourceMapConsumer } = require('source-map-js')

const A = `<template>
  <Comp>
    <div v-if="ok">hello</div>
  </Comp>
</template>
`

const others = {
  'B.vue': `<template>
<p>
a
different
file
</p>
</template>
`,
  'C.vue': `<template><p>one line</p></template>
`,
}

const divOffset = A.indexOf('<div')
const divLines = A.slice(0, divOffset).split('\n')
console.log(
  'expected'.padEnd(28),
  `${divLines.length}:${divLines[divLines.length - 1].length}`,
  JSON.stringify(A.slice(divOffset, A.indexOf('</div>') + 6)),
)

let run = 0
function compileA(otherName) {
  const filename = `A${++run}.vue`
  const { descriptor } = parse(A, { filename })
  if (otherName) parse(others[otherName], { filename: otherName })

  const { code, ast, map } = compileTemplate({
    id: 'a',
    filename,
    source: descriptor.template.content,
    ast: descriptor.template.ast,
  })

  const ifNode = ast.children[0].children[0]
  const before = code.slice(0, code.indexOf('() => [')).split('\n')
  const mapped = new SourceMapConsumer(map).originalPositionFor({
    line: before.length,
    column: before[before.length - 1].length,
  })
  console.log(
    `parse(${filename})${otherName ? `, parse(${otherName})` : ''}`.padEnd(28),
    `${mapped.line}:${mapped.column}`,
    JSON.stringify(ifNode.loc.source),
  )
}

compileA()
compileA('B.vue')
compileA('C.vue')
```

The script parses `A.vue`, optionally parses another SFC, and then compiles the template of `A.vue` from `descriptor.template.ast`, as vue-loader and `@vitejs/plugin-vue` do. For each run it prints where the generated default slot function `() => [` points in the source map and the `loc.source` of the `v-if` node. Each run uses its own filename because `parse()` caches descriptors: a cached AST is already transformed, so `resolveTemplateAST` parses it again and the problem disappears.

### What is expected?

The slot function maps to `3:4` (the `<div v-if>`) and the `v-if` node has `loc.source` `<div v-if="ok">hello</div>`, no matter what was parsed before:

```
expected                     3:4 "<div v-if=\"ok\">hello</div>"
parse(A1.vue)                3:4 "<div v-if=\"ok\">hello</div>"
parse(A2.vue), parse(B.vue)  3:4 "<div v-if=\"ok\">hello</div>"
parse(A3.vue), parse(C.vue)  3:4 "<div v-if=\"ok\">hello</div>"
```

### What is actually happening?

Line, column and source of the `v-if` node are computed against the text of the file parsed last:

```
expected                     3:4 "<div v-if=\"ok\">hello</div>"
parse(A1.vue)                3:4 "<div v-if=\"ok\">hello</div>"
parse(A2.vue), parse(B.vue)  4:7 "nt\nfile\n</p>\n</template>\n"
parse(A3.vue), parse(C.vue)  1:24 "></template>\n"
```

### System Info

```shell
Node.js 24.19.0, Windows 11. The problem is in the compiler and does not depend on the platform.
```

### Any additional comments?

`processIf` in `transforms/vIf.ts` creates the IF node with `loc: cloneLoc(node.loc)` (#12131). `cloneLoc` calls `getLoc(loc.start.offset, loc.end.offset)`, which takes line and column from `tokenizer.getPos()` and `source` from `currentInput`. Both are module-level and keep the state of the last `baseParse()` call. Since 3.4 compiler-sfc reuses `descriptor.template.ast`, so the transform runs well after the parse, and a bundler usually parses other `.vue` files in between.

In the generated code this shows up when the `v-if` element is the first child of an implicit default slot, because the slot function takes `children[0].loc`. We hit it with `<Transition><component v-if="current" :is="current" /></Transition>` in a webpack 5 + vue-loader 17 build: `popup.js.map` differed between builds of the same commit, since the order in which modules are parsed varies. `compileScript(descriptor, { inlineTemplate: true })` is affected the same way: the slot segments point to wrong positions or are dropped.

Copying the location instead of recomputing it fixes the reproduction, and the IF node still gets its own position objects, as #12131 intended:

```ts
export function cloneLoc(loc: SourceLocation): SourceLocation {
  return {
    start: { ...loc.start },
    end: { ...loc.end },
    source: loc.source,
  }
}
```
