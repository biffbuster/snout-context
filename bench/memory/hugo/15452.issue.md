# Make emojify return a string (issue #15452)

I got this mailed as a security report, and I'll create this as a security hardening issue to set the boundaries: I'll label this as a security hardening issue, but I'm **not** creating a GitHub Security Advisory/CVE for (that's surprisingly lot of work, but that's not the reason).

The gist of it is in:

```handlebars
{{ .Title | transform.Emojify }}
```

`transform.Emojify` returns `template.HTML` and would mark the potentially unsafe `.Title` (from potentially untrusted content) as safe. But the templates are marked as trusted, the `transform.Emojify`'s return type is clearly documented, and we have plenty of other cases where a user can create unsafe markup. E.g. the above is technically similar to:

```handlebars
{{ .Title | safeHTML }}
```

Thanks to @Reload3d for reporting this issue.
