# Support subdirectory paths in .Render (issue #15056)

Allow `.Render "subdir/myview"` to look up a content view template named `myview` starting from `layouts/{page-path}/subdir/`, walking up the tree as usual. Note that `subdir` is not part of the tree.

This construct worked in earlier versions; we removed it in v0.146.0 with implementation of the new template system.

The purpose of such a construct is to organize content views in a dedicated directory.

Reference: <https://discourse.gohugo.io/t/silent-error-with-render-function-in-v0-163-2-extended-withdeploy/57290/9>

Comment by jmooring:

An important implementation detail... as we work our way back up the tree to find a matching content view template, I believe the match should be based on the entire argument passed to the `Render` method... that is how it worked in v0.145.0 and earlier.

That mean that if you call `.Render "a/b/c"` from `s1/p1/page.html`, we need to look for:

1. `layouts/s1/p1/a/b/c.html`
2. `layouts/s1/a/b/c.html`
3. `layouts/a/b/c.html`

Or to put it another way, we should **not** match:

1. `layouts/s1/p1/a.html`
1. `layouts/s1/a.html`
1. `layouts/a.html`

This test contains the affirmative assertions in the above:

```go
// See issue 15056.
func TestRenderViewSubdir(t *testing.T) {
	t.Parallel()

	files := `
-- hugo.toml --
disableKinds = ['home','rss','section','sitemap','taxonomy','term']
-- content/s1/p1.md --
---
title: p1
---
-- layouts/s1/p1/page.html --
{{ .Render "a" }}|{{ .Render "b" }}|{{ .Render "c" }}|{{ .Render "views/d" }}|{{ .Render "views/e" }}|{{ .Render "views/f" }}
-- layouts/s1/p1/a.html --
a{{- /**/ -}}
-- layouts/s1/b.html --
b{{- /**/ -}}
-- layouts/c.html --
c{{- /**/ -}}
-- layouts/s1/p1/views/d.html --
d{{- /**/ -}}
-- layouts/s1/views/e.html --
e{{- /**/ -}}
-- layouts/views/f.html --
f{{- /**/ -}}
`

	b := Test(t, files)
	b.AssertFileContent("public/s1/p1/index.html", "a|b|c|d|e|f")
}
```

Do not proceed with any changes until https://github.com/gohugoio/hugo/issues/15057 is addressed one way or the other.
