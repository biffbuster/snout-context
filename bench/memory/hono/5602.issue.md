# ETag middleware does not cancel the response body stream when returning 304 Not Modified (issue #5602)

### What version of Hono are you using?

4.13.16

### What runtime/platform is your app running on? (with version if possible)

Node.js v25.9.0 / Bun / Cloudflare Workers (any runtime supporting Web Streams)

### What steps can reproduce the bug?

When `etag()` returns `304 Not Modified`, `src/middleware/etag/index.ts` replaces `c.res` with `new Response(null, { status: 304, ... })` without cancelling `res.body`:

```ts
import { Hono } from 'hono'
import { etag } from 'hono/etag'

let cancelled = false

const app = new Hono()
app.use('/stream', etag())
app.get('/stream', (c) => {
  const stream = new ReadableStream<Uint8Array>({
    pull(controller) {
      controller.enqueue(new TextEncoder().encode('chunk'))
    },
    cancel() {
      cancelled = true
    },
  })
  return c.body(stream, 200, { ETag: '"stream-v1"' })
})

const res = await app.request('http://localhost/stream', {
  headers: { 'If-None-Match': '"stream-v1"' },
})

console.log(res.status) // 304
console.log(cancelled)  // false (expected: true)
```

Even when `ETag` is not preset on the response, `res.clone().body` tees `res.body` to compute the SHA-1 digest, and only the cloned branch is consumed. When `matched` is `true`, replacing `c.res` without calling `await res.body?.cancel()` leaves the original tee branch uncancelled.

### What is the expected behavior?

When `etag()` replaces `c.res` with a `304 Not Modified` response, the discarded `res.body` stream should be cancelled (`await res.body?.cancel()`) so underlying stream resources (`cancel()` callbacks or teed stream buffers) are released.

### What do you see instead?

`res.body` is not cancelled when `etag()` overwrites `c.res` on a `304 Not Modified` match (`cancelled` remains `false`).

### Additional information

In `src/middleware/etag/index.ts`:

```ts
    if (matched) {
      await res.body?.cancel()
      c.res = new Response(null, {
        status: 304,
```
