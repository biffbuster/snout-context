# `c.header()` crashes after consumption of the finalized res body (issue #5586)

### What version of Hono are you using?

4.13.13

### What runtime/platform is your app running on? (with version if possible)

Cloudflare Workers

### What steps can reproduce the bug?

In a middleware, call the `c.header()` or a dependent such as `c.redirect()` or `setCookie()` after consumption of the **finalized** res body.
```typescript
import { Hono } from "hono";
import { createMiddleware } from "hono/factory";

const app = new Hono();
const middleware = createMiddleware(async (c, next) => {
  await next();
  await c.res.text();
  c.header("x-something", "hey"); // will throw
  c.res = c.text("alternative response");
});

export default app
  .use(middleware)
  .get("*", (c) => c.text("ok"));
```

### What is the expected behavior?

Always respond `"alternative response"` with a header `x-something: hey` successfully.

### What do you see instead?

The most simple solution: user shall set, on his responsibility, `c.finalized = false` just after consumption of the res body. However, the `finalized` property, though public, seems to be undocumented officially at present. Resetting as `c.res = undefined` is pointless because `finalized` is still true.
[link removed]

Another solution is to clear `c.finalized = false` when resetting as `c.res = undefined`. Since `set res` accepts `undefined` currently, this sounds semantically reasonable to me.

Some other options also come to my mind, but they are more complicated: `get finalized`, method with a callback parameter `(old: Response) => Response` to replace res, consumed-aware `Response` wrapping, etc.

### Additional information

After such consumption, it is user's responsibility to replace `c.res` with new `Response`, but I think `c.header()` should not expect the res is entirely valid even if `finalized`.
[link removed]
This behavior was introduced by #4055, related discussion has been in progress in #4992, and the natural fix will depend on it.
