# prettyJSON middleware does not cancel the original response body stream when replacing c.res (issue #5603)

### What version of Hono are you using?

4.13.16

### What runtime/platform is your app running on? (with version if possible)

Node.js v24.22.1 (also affects Web Standard runtimes such as Cloudflare Workers, Deno, and Bun)

### What steps can reproduce the bug?

When the `prettyJSON` middleware (`src/middleware/pretty-json/index.ts`) formats a JSON response, it clones the response to parse the JSON (`obj = await c.res.clone().json()`) and then replaces `c.res` with a newly constructed `Response` without cancelling `c.res.body`:

```ts
import { Hono } from 'hono'
import { prettyJSON } from 'hono/pretty-json'

const app = new Hono()
let originalRes: Response | undefined

app.use('*', prettyJSON({ force: true }))
app.get('/x', () => {
  const stream = new ReadableStream({
    start(controller) {
      controller.enqueue(new TextEncoder().encode('{"message":"Hono!"}'))
      controller.close()
    },
  })
  originalRes = new Response(stream, {
    headers: { 'Content-Type': 'application/json' },
  })
  return originalRes
})

const res = await app.request('http://localhost/x')
await res.text()

const readResult = await originalRes!.body!.getReader().read()
console.log({ done: readResult.done })
// Actual:   { done: false }
// Expected: { done: true }
```

In `src/middleware/pretty-json/index.ts` (lines 58–63):

```ts
      try {
        obj = await c.res.clone().json()
      } catch {
        // e.g. an empty 204 response or a body that is not valid JSON
        return
      }
      c.res = new Response(JSON.stringify(obj, null, options?.space ?? 2), c.res)
```

Calling `c.res.clone()` tees `c.res.body` into two `ReadableStream` branches and `.json()` consumes only the cloned branch. When `c.res` is overwritten with `new Response(...)`, the original `c.res.body` branch is discarded without calling `await c.res.body?.cancel()`.

### What is the expected behavior?

Before replacing `c.res` with the prettified `Response`, the middleware should cancel the discarded original response stream (`await c.res.body?.cancel()`).

### What do you see instead?

`c.res.body` is not cancelled when `c.res` is replaced with the prettified JSON response, leaving the unconsumed tee branch open in memory.

### Additional information

Calling `await c.res.body?.cancel()` right before `c.res = new Response(JSON.stringify(obj, null, options?.space ?? 2), c.res)` resolves the issue.

Comment by hamarshehmhmd:

I can confirm this on main (c91b60a). `clone()` tees the body, `.json()` only drains the clone's branch, and then the original branch gets dropped when `c.res` is replaced. Your one-liner fixes it. Here it is as a patch with a regression test, in case that saves someone a step:

```diff
--- a/src/middleware/pretty-json/index.ts
+++ b/src/middleware/pretty-json/index.ts
@@
         // e.g. an empty 204 response or a body that is not valid JSON
         return
       }
+      // Discard the original body: clone() tee'd it, and only the cloned branch was read
+      await c.res.body?.cancel()
       c.res = new Response(JSON.stringify(obj, null, options?.space ?? 2), c.res)
```

```ts
  it('Should cancel the original response body after replacing it', async () => {
    const app = new Hono()
    let originalRes: Response | undefined
    app.use('*', prettyJSON({ force: true }))
    app.get('/x', () => {
      const stream = new ReadableStream({
        start(controller) {
          controller.enqueue(new TextEncoder().encode('{"message":"Hono!"}'))
          controller.close()
        },
      })
      originalRes = new Response(stream, { headers: { 'Content-Type': 'application/json' } })
      return originalRes
    })
    const res = await app.request('http://localhost/x')
    expect(await res.text()).toBe('{\n  "message": "Hono!"\n}')
    const result = await originalRes!.body!.getReader().read()
    expect(result.done).toBe(true)
  })
```

The cancel only runs after the clone parsed successfully, so the invalid-JSON / 204 / already-consumed pass-through paths stay the same.

Tested: the new test fails without the change and passes with it. The rest of `pretty-json/index.test.ts` (12 tests) still passes. I also checked the tee behaviour on plain Node 20: after `clone().json()`, the original branch reads `done: false` without the cancel and `done: true` with it.
