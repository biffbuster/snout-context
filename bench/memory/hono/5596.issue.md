# req.query(key) matches across query separators inside the requested key (issue #5596)

### What version of Hono are you using?

4.13.14; current main [commit removed]

### What runtime/platform is your app running on? (with version if possible)

Node.js v24.22.1 on Windows

### What steps can reproduce the bug?

From current `main` (`[commit removed]`), run this public-API probe (the test import below is from `src/utils`):

```ts
import { Hono } from '../hono'

const app = new Hono()
app.get('/', (c) => c.json({
  amp: c.req.query('a&b') ?? null,
  equals: c.req.query('a=b') ?? null,
  ampMany: c.req.queries('a&b') ?? null,
  equalsMany: c.req.queries('a=b') ?? null,
  all: c.req.query(),
}))

for (const url of ['/?a&b=3', '/?a=b=3', '/?a%26b=3', '/?a%3Db=3']) {
  console.log(url, await (await app.request(url)).json())
}
```

The encoded URLs are controls where `a&b` or `a=b` really is one key.

### What is the expected behavior?

For `/?a&b=3`, `c.req.query('a&b')` should be absent, because the query has separate `a` and `b` keys. For `/?a=b=3`, `c.req.query('a=b')` should also be absent, because the query has one `a` key whose value is `b=3`. This should agree with `c.req.queries(key)`, `c.req.query()`, and `URLSearchParams.get(key)`. The encoded controls should return `3` for their respective keys.

### What do you see instead?

`/?a&b=3`: `query('a&b')` returns `3`, while `queries('a&b')` is undefined and `query()` returns `{ a: '', b: '3' }`.

`/?a=b=3`: `query('a=b')` returns `3`, while `queries('a=b')` is undefined and `query()` returns `{ a: 'b=3' }`.

`/?a%26b=3` and `/?a%3Db=3` correctly return `3` for the encoded key.

### Additional information

The single-key fast path in `src/utils/url.ts` searches for the literal key substring after `?` or `&` and checks only the character after the requested key. It does not reject an unescaped `&` or `=` inside the requested key, so it can match across query syntax. This is distinct from the encoded duplicate-order behavior discussed in #5580.

Comment by Rohan-Dedhia:

I'd like to take this issue!

I reproduced the discrepancy in \src/utils/url.ts\: the single-key fast path checks \key.indexOf('%') === -1 && key.indexOf('+') === -1\, but does not exclude query delimiters \&\ or \=\, causing keys containing \&\ or \=\ (e.g. \
eq.query('a&b')\ on \/?a&b=3\) to match across parameter boundaries.

Plan:
- Exclude \&\ and \=\ from the unencoded fast-path (\key.indexOf('&') === -1 && key.indexOf('=') === -1\) so queries with those characters fall back to the robust parser path.
- Add regression test cases covering unencoded and encoded delimiter scenarios in \src/utils/url.test.ts\.
