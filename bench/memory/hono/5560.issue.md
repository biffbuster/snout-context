# `hono/jsx`: ref objects are rendered as `ref="[object Object]"` in SSR (issue #5560)

### What version of Hono are you using?

4.13.13 (also reproduced on main at `33622444`)

### What runtime/platform is your app running on? (with version if possible)

Node.js 24. It is server-side rendering, so it should not depend on the runtime.

### What steps can reproduce the bug?

When a ref created with `useRef()` is passed to an element and rendered on the server, `ref` is output as an attribute.

```tsx
const App = () => {
  const ref = useRef(null)
  return <a ref={ref} href='/'>x</a>
}

console.log((<App />).toString())
```

A function ref (`ref={(el) => {}}`) is not output.

### What is the expected behavior?

`<a href="/">x</a>`. Same as React, refs should not appear in the server HTML.

### What do you see instead?

`<a ref="[object Object]" href="/">x</a>`

### Additional information

- For function values, only `on*` and `ref` are ignored. But an object value is turned into a string as is.
- A possible fix with tests: [link removed] . It skips `ref` like `children`, whatever the value type is.

Comment by duongynhi000005-oss:

Hi team, I traced #5560 in `src/jsx/base.ts` and prepared a fix.

### Root Cause
In `src/jsx/base.ts` (lines 256–299), SSR attribute serialization skips `children` at line 256 (`if (key === 'children')`), but only skips `ref` inside the `typeof v === 'function'` branch at line 291. When an object ref from `useRef()` (`{ current: ... }`) is passed, `typeof v === 'object'`, so it falls through to the `else` branch at line 294 and renders `ref="[object Object]"` into the SSR HTML output.

### Proposed Fix
Skip `key === 'ref'` alongside `key === 'children'` at line 256 of `src/jsx/base.ts`:
```diff
-      if (key === 'children') {
-        // skip children
+      if (key === 'children' || key === 'ref') {
+        // skip children and ref
       } else if (key === 'style' && typeof v === 'object') {
```

I have this fix ready on my fork branch and can open a PR right away!
