# parseResponse returns text for JSON Content-Type with whitespace before a semicolon (issue #5605)

### What version of Hono are you using?

4.13.16; main at [commit removed].

### What runtime/platform is your app running on? (with version if possible)

Reproduced against the source checkout on macOS with Node.js 22.23.1 and Bun 1.3.8. This was found through source inspection and local reproduction, not a production incident.

### What steps can reproduce the bug?

```ts
import { Hono } from 'hono'
import { hc, parseResponse } from 'hono/client'

const app = new Hono().get('/data', (c) =>
  c.json({ ok: true }, 200, {
    'Content-Type': 'application/json ; charset=utf-8',
  })
)
const client = hc<typeof app>('http://localhost', {
  fetch: app.request,
})
const result = await parseResponse(client.data.$get())
console.log(typeof result, result)
console.log(result.ok)
```

The package-import example expresses normal usage. Local verification imported the corresponding checked-out source directly, using the same hc → app.request → parseResponse path.

### What is the expected behavior?

An object `{ ok: true }`, and `result.ok === true`, just as with `application/json; charset=utf-8`.

RFC 9110 sections [8.3.1](https://www.rfc-editor.org/rfc/rfc9110.html#section-8.3.1) and [5.6.6](https://www.rfc-editor.org/rfc/rfc9110.html#section-5.6.6) allow optional whitespace before the parameter semicolon.

### What do you see instead?

The result is the string `'{"ok":true}'`, despite the RPC return type being inferred as an object. `result.ok` is `undefined`.

Using a horizontal tab before the semicolon, or a structured JSON media type such as `application/problem+json ; charset=utf-8`, has the same result. For a JSON 400 response, `DetailedError.detail.data` is also a string instead of a parsed object.

### Additional information

`detectResponseType()` in `src/client/fetch-result-please.ts` splits Content-Type at `;` but does not trim the resulting media type before testing the JSON regex.

The new repository-native regression cases fail on the original source (four success-response cases and two error-response cases). Trimming the media type makes the client suite pass: 181 tests. The test TypeScript project, project checks, and package build also pass locally, with warnings in existing code. The complete test suite and remote CI were not run.

AI assistance was used for investigation, tests, and this draft. No existing issue or PR covering this specific whitespace behavior was found in searches on 2026-11-04.
